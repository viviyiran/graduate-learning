## 一、数据结构基础

### 1. 数据、数据元素、数据项

- **数据**：能够被计算机识别、存储和处理的信息。
- **数据元素**：数据的基本单位，例如“一名学生的一条完整记录”。
- **数据项**：组成数据元素的更小单位，例如学生记录中的“学号、姓名、性别”。

容易混淆：

> 数据元素是一个整体，数据项是这个整体中的组成部分。

---

### 2. 数据结构研究什么

数据结构主要研究三方面：

1. **逻辑结构**：数据元素之间是什么关系。
2. **存储结构**：数据在计算机中如何存放。
3. **数据运算**：对数据进行查找、插入、删除、排序等操作。

可以记成：

```text
数据结构
├─ 逻辑结构：看“关系”
├─ 存储结构：看“怎么存”
└─ 数据运算：看“怎么操作”
```

---

### 3. 逻辑结构

常见逻辑结构包括：

- **集合结构**：元素属于同一个集合，没有明显前后关系。
- **线性结构**：元素之间呈一对一的前后关系。
- **树形结构**：呈一对多关系。
- **图结构**：呈多对多关系。

判断时重点看：

> 描述的是“元素之间的关系”，就是逻辑结构。

---

### 4. 存储结构

本章重点接触：

- **顺序存储**：数据在内存中连续存放，例如数组。
- **链式存储**：数据在内存中可以不连续，通过指针等方式连接。

重要理解：

> 同一种逻辑结构可以采用不同的存储方式。

例如线性表既可以用顺序表实现，也可以用链表实现。

---

## 二、算法基础

### 1. 什么是算法

用自己的话概括：

> 算法就是按照一系列明确步骤解决某个问题的方法。

算法不一定是在“计算数值”，查找、排序、遍历等也都是算法。

---

### 2. 算法的基本特性

需要掌握：

- **有穷性**：必须能在有限步骤内结束。
- **确定性**：每一步必须明确，不能含糊。
- **可行性**：每一步都能够实际执行。
- **输入**：可以有 0 个或多个输入。
- **输出**：必须至少有 1 个输出。

---

### 3. 算法设计目标

除了“能得到正确答案”，还要考虑：

- 正确性
- 可使用性
- 可读性
- 健壮性
- 高效率
- 低存储量

---

## 三、时间复杂度

### 1. 时间复杂度研究什么

时间复杂度不是直接研究“程序跑了几秒”，而是研究：

> 随着问题规模 `n` 增大，算法基本操作执行次数的增长趋势。

---

### 2. 本章掌握的常见复杂度

从增长速度由慢到快：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²)
```

一般情况下，增长越慢，算法越高效。

---

### 3. O(1)

固定执行若干次，与 `n` 无关：

```cpp
cout << "A";
cout << "B";
cout << "C";
```

即使执行 3 次、10 次、100 次，只要次数固定，都属于：

```text
O(1)
```

---

### 4. O(n)

例如：

```cpp
for (int i = 0; i < n; i++)
{
    cout << i;
}
```

循环执行约 `n` 次，因此是：

```text
O(n)
```

`2n`、`5n`、`n/2`、`100n` 都忽略常数，最终记作 `O(n)`。

---

### 5. O(n²)

典型双重循环：

```cpp
for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        // ...
    }
}
```

执行次数约为：

```text
n × n = n²
```

因此：

```text
O(n²)
```

---

### 6. O(log n)

当变量每次成倍变化时，通常想到 `O(log n)`。

```cpp
for (int i = 1; i <= n; i = i * 2)
{
    cout << i;
}
```

`i` 的变化：

```text
1 → 2 → 4 → 8 → 16 → ...
```

因此：

```text
O(log n)
```

重要规律：

```text
每次 +固定值 / -固定值 → 通常 O(n)
每次 ×固定倍数 / ÷固定倍数 → 通常 O(log n)
```

---

### 7. O(n log n)

如果外层执行 `n` 次，内层每次执行约 `log n` 次，则：

```text
n × log n
```

时间复杂度为：

```text
O(n log n)
```

---

### 8. 并列循环与嵌套循环

- **并列循环**：执行次数通常相加。
- **嵌套循环**：执行次数通常相乘。
- 最终还要保留增长最快的项。

例如：

```text
n + n² → O(n²)
```

---

## 四、空间复杂度

空间复杂度研究：

> 随着问题规模 `n` 增大，算法所需存储空间的增长趋势。

常见情况：

```cpp
int x;
int y;
int z;
```

→ `O(1)`

```cpp
int a[n];
```

→ `O(n)`

```cpp
int a[n][n];
```

→ `O(n²)`

固定长度数组：

```cpp
int a[100];
```

虽然有 100 个元素，但 100 是固定常数，因此仍为 `O(1)`。

---

## 五、时间与空间的权衡

不能只根据某一个复杂度直接判断算法一定更好。

例如：

```text
算法 A：时间 O(n)，空间 O(n)
算法 B：时间 O(n²)，空间 O(1)
```

A 更快但占用更多空间，B 更省空间但可能更慢。

实际选择要结合：

- 数据规模
- 时间要求
- 内存限制
- 实际应用场景

> 成倍增长或成倍缩小，往往对应对数级复杂度。

- `for`

# 七、容易出错的地方

1. **数据元素与数据项混淆**
   - 一名学生完整记录 → 数据元素
   - 学号 / 姓名 / 性别 → 数据项

2. **逻辑结构与存储结构混淆**
   - 看“元素之间的关系” → 逻辑结构
   - 看“计算机里怎么存” → 存储结构

3. **把数据结构等同于存储方式**
   - 正确理解：`数据结构 = 逻辑结构 + 存储结构 + 数据运算`

4. **把时间复杂度理解成实际运行时间**
   - 时间复杂度描述的是操作次数随 `n` 增大的增长趋势。

5. **看到一个循环就判断 O(n)**
   - `for (int i = 0; i < 10; i++)` 固定 10 次，因此是 `O(1)`。

6. **看到两层循环就判断 O(n²)**
   - 如果内层固定 5 次，总复杂度仍可能是 `O(n)`。

7. **O(log n) 容易判断错**
   - `i++` → 通常 `O(n)`
   - `i *= 2` / `i /= 2` → 通常 `O(log n)`

8. **空间复杂度容易忽略数组**
   - `int a[n]` 会随 `n` 增大，因此空间复杂度是 `O(n)`。
