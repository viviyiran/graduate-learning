## 二、今天最重要的知识点

### 1. 数据结构不等于“数据怎么存”

数据结构主要研究三个方面：

```text
数据结构
├── 逻辑结构：数据元素之间是什么关系
├── 存储结构：这些数据在计算机中怎么存
└── 数据运算：对数据进行查找、插入、删除、排序等操作
```

今天最重要的一句话：

> **逻辑结构看“关系”，存储结构看“怎么实现”。**

### 2. 常见逻辑结构

逻辑结构主要可以分为：

- **集合结构**：元素之间除了属于同一个集合外，没有明显的前后关系。
- **线性结构**：元素之间通常是一对一的前后关系。
- **树形结构**：元素之间通常是一对多的层次关系。
- **图结构**：元素之间可以是多对多的关系。

例如：

```text
排队关系 → 线性结构
公司组织架构 → 树形结构
好友关系 → 图结构
```

### 3. 顺序存储和链式存储

- **顺序存储**：数据在内存中连续存放，数组是最典型的例子。
- **链式存储**：数据在内存中的位置可以不连续，通过指针等方式建立联系。

需要注意：

> **链表和链式存储不是完全相同的概念。**

链表通常指线性表的一种链式实现，而链式存储是一种更一般的存储方式，树等结构也可以采用链式存储。

### 4. 数据元素和数据项

以学生信息为例：

```text
一个学生记录 = 一个数据元素
学号、姓名、性别 = 数据项
```

之前容易把“学号、姓名、性别”误认为数据元素，实际上它们是组成一个数据元素的更小单位。

## 三、算法部分

### 1. 什么是算法

我现在的理解：

> **算法就是按照明确、有限的步骤去解决一个问题的方法。**

算法不一定是做数学计算，例如查找、排序、遍历也都是算法。

### 2. 算法的基本特性

算法需要具备：

- **有穷性**：最终必须能够结束。
- **确定性**：每一步的含义必须明确，不能模棱两可。
- **可行性**：每一步都应该能够实际执行。
- **输入**：可以有0个或多个输入。
- **输出**：必须至少有一个输出。

容易混淆的是“算法特性”和“算法设计目标”。算法设计时还需要考虑正确性、可读性、健壮性、效率和存储量等。

## 四、时间复杂度

### 1. 时间复杂度真正研究什么

时间复杂度不是直接研究程序“运行了几秒”，而是：

> **随着问题规模 `n` 增大，算法中基本操作执行次数的增长趋势。**

因此，大 O 表示的是增长级别，而不是某一次程序的实际运行时间。

### 2. 今天掌握的常见时间复杂度

| 时间复杂度 | 直观理解 |
| --- | --- |
| `O(1)` | 执行次数固定，不随 `n` 增大 |
| `O(log n)` | 每次成倍增加或缩小，例如 `×2`、`÷2` |
| `O(n)` | 执行次数大致和 `n` 成正比 |
| `O(n log n)` | 一层 `n` 次循环中嵌套一个 `log n` 级过程 |
| `O(n²)` | 执行次数大致和 `n²` 成正比 |

增长速度从慢到快：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²)
```

一般来说，增长越慢，算法在大规模数据下越有优势。

### 3. 判断循环复杂度时的规律

#### 一层和 `n` 有关的循环

```cpp
for (int i = 0; i < n; i++) {
    ...
}
```

通常是：

```text
O(n)
```

#### 两层都和 `n` 有关的嵌套循环

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        ...
    }
}
```

通常是：

```text
O(n²)
```

#### 内层只是固定次数

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < 10; j++) {
        ...
    }
}
```

总执行次数约为 `10n`，忽略常数后：

```text
O(n)
```

#### 成倍增长或缩小

```cpp
while (i < n) {
    i = i * 2;
}
```

或者：

```cpp
while (i > 1) {
    i = i / 2;
}
```

通常是：

```text
O(log n)
```

### 4. 大 O 化简时要注意

- 忽略常数：`O(5n)` → `O(n)`
- 忽略低阶项：`O(n² + n)` → `O(n²)`
- 并列循环一般先相加，再保留增长最快的项。
- 嵌套循环不能只看“有几层”，还要看每一层到底执行多少次。

## 五、空间复杂度

空间复杂度研究：

> **随着问题规模 `n` 增大，算法所需存储空间的增长趋势。**

例如：

```cpp
int x;
int y;
int z;
```

只使用固定数量变量：

```text
O(1)
```

而：

```cpp
int a[n];
```

数组长度随着 `n` 增大：

```text
O(n)
```

二维数组：

```cpp
int a[n][n];
```

空间复杂度：

```text
O(n²)
```

时间复杂度和空间复杂度之间有时需要权衡，例如为了提高运行速度而额外使用内存，也就是常说的“用空间换时间”。

## 六、今天最容易出错的地方

### 1. 容易混淆逻辑结构和存储结构

之前会把 `A → B → C → D` 判断成存储结构。

现在需要记住：

```text
描述元素之间的关系 → 逻辑结构
描述计算机里面怎么存 → 存储结构
```

### 2. 容易把“链表”和“链式存储”混为一谈

链表通常指线性表的链式实现，而链式存储是一种更广泛的存储方式。

### 3. 容易把数据元素和数据项混淆

```text
一个学生 → 数据元素
学生的学号、姓名、性别 → 数据项
```

### 4. 容易看到两层循环就直接判断为 `O(n²)`

实际上要看内层循环是否也随着 `n` 增长。

例如：

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < 10; j++) {
        ...
    }
}
```

虽然有两层循环，但实际是 `10n` 次，因此是 `O(n)`。

### 5. `O(log n)` 还需要继续巩固

今天最容易错的是这种代码：

```cpp
i = i * 2;
```

或者：

```cpp
i = i / 2;
```

之前容易误判成 `O(n)` 或 `O(n²)`。

现在要形成条件反射：

```text
每次 +1 / -1 → 通常想到 O(n)
每次 ×2 / ÷2 → 通常想到 O(log n)
```

### 6. 时间复杂度不能说成“程序运行了多久”

更准确的理解是：

> **基本操作次数随 `n` 增大的增长趋势。**

实际运行秒数还会受到硬件、编译器、程序实现等因素影响。

### 7. 空间复杂度要抓住真正随 `n` 增长的部分

例如：

```cpp
int a[n];
int x;
int y;
```

虽然只有两个固定变量，但数组 `a[n]` 会随着 `n` 变大，所以整体空间复杂度仍然是：

```text
O(n)
```
